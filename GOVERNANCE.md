# Project Governance

This document describes how decisions are made, how contributions are managed,
and how maintainers collaborate to ensure the long‑term health of the project.

---

## 1. Roles

### 🧑‍💻 Contributors
Anyone who submits:

- Code
- Documentation
- Bug reports
- Feature requests

Contributors help shape the project but do not have merge permissions.

---

### 🔧 Maintainers
Maintainers are responsible for:

- Reviewing and merging pull requests
- Managing releases
- Enforcing the Code of Conduct
- Setting project direction
- Approving major changes

Maintainers have commit access.

---

### 🛠 Lead Maintainer
The lead maintainer:

- Oversees project vision
- Coordinates releases
- Resolves disputes
- Has final decision authority when consensus cannot be reached

---

## 2. Decision-Making

### Consensus‑Driven
Most decisions are made through discussion in:

- Pull requests
- Issues
- GitHub Discussions

If consensus cannot be reached, maintainers vote.

### Maintainer Vote
- Each maintainer gets one vote
- Simple majority wins
- Lead maintainer breaks ties

---

## 3. Contribution Workflow

1. Fork the repository  
2. Create a feature branch  
3. Submit a pull request  
4. Maintainers review  
5. Changes requested (if needed)  
6. Maintainer merges when approved  

All contributions must:

- Pass tests
- Follow code style
- Include documentation updates (if needed)

---

## 4. Release Management

Releases follow:

- Semantic Versioning
- Automated pipelines (GitHub Actions)
- bump2version for version control

Only maintainers may publish releases.

---

## 5. Adding or Removing Maintainers

### Adding
A contributor may become a maintainer if they:

- Demonstrate consistent, high‑quality contributions
- Show good judgment and collaboration
- Are approved by existing maintainers

### Removing
A maintainer may be removed if they:

- Become inactive for an extended period
- Violate the Code of Conduct
- Act against project interests

Removal requires a majority vote.

---

## 6. Conflict Resolution

If disagreements arise:

1. Discuss respectfully in the issue or PR  
2. Seek consensus  
3. If unresolved, maintainers vote  
4. Lead maintainer makes final decision  

---

## 7. Transparency

All decisions, discussions, and votes occur publicly on GitHub unless they involve:

- Security issues
- Sensitive personal matters

---

## 8. Amendments

This governance document may be updated by:

- Maintainer vote  
- Lead maintainer approval  

---

Thank you for helping maintain a healthy, collaborative project!
